# Decisions

Choices the brief didn't settle, and why they went the way they did.

## Extraction

- **Heuristic-first extraction, LLM fallback.** The brief names LLM extraction; a deterministic
  tabular parser handles standard layouts instead, so the golden PDF suite runs with no network
  and no key, and the product is fully usable without one. The LLM path (same zod schema, one
  retry, then needs-review) covers layouts the parser can't read. This keeps the DoD testable and
  makes the privacy story unconditional rather than opt-in.
- **A report either extracts cleanly or goes to the review queue.** Nothing partially-read is
  written to the timeline. A half-transcribed lab result is worse than none, because it looks
  authoritative.
- **Fixture PDFs are generated by a committed script (pdf-lib)** rather than checked in as opaque
  binaries. Layouts stay editable and diffable; the expected-value JSON beside each one is
  hand-authored from the values printed into the PDF, never copied out of parser output — so the
  suite tests the parser rather than agreeing with it.
- **Ambiguous dates resolve by separator convention.** Slash dates read month-first (US), dot
  dates day-first (European), ISO as written. `06/12/2021` has no correct answer without a
  locale; the rule is documented in `parse.ts` and covered by tests.

## Clinical modelling

- **Reference ranges always come from the report the value was printed on.** The marker registry
  carries units and conversions but never a "normal range" of its own. Labs legitimately differ,
  and a value can be in range at one lab and outside it at another — the marker detail table
  shows exactly that. Shipping our own ranges would be practising medicine.
- **Charts draw a stepped reference band, one segment per sample.** The first version showed a
  single band only when every lab agreed, and gave up otherwise — which was most multi-lab
  markers. Stepping is both more useful and more truthful: each point is drawn against the range
  it was actually measured against.
- **Chart x-axis is time-proportional, not index-spaced.** Samples four years apart must not look
  the same as samples four weeks apart; the original index spacing misrepresented every irregular
  sampling history.
- **The insights engine ranks but does not triage.** `significance` orders markers by how far
  outside the printed range they sit and how much they moved. It is presentation ordering, and
  the UI says so — it is not a severity score, and no wording implies clinical priority.

## Product scope

- **Local export and import were added beyond the brief.** The brief rules out *sharing*; a
  record you can only ever read inside one browser profile is one you don't really own, and one
  cleared cache from losing. Export writes a file to disk and import reads one back — no network
  involved, so the privacy guarantee is unchanged.
- **A printable visit summary is the product's actual output.** The brief asks for a question
  list; on its own that omits the numbers a doctor will immediately ask for. The summary page
  pairs the findings with the questions on one printable sheet, and works fully without an API
  key (only the drafted questions need one).

## Design

- **Light-first, with a real dark mode** — a deliberate departure from the shared dark-only
  design system, on the user's instruction to match what this category actually looks like.
  Medical records read as paper: warm off-white, near-black ink, hairline rules. Dark mode is a
  separately-tuned palette rather than an inversion.
- **Colour is functional only.** Green means inside the printed range, red means outside, amber
  means a large move. Nothing else in the interface is coloured, so colour never has to be
  interpreted. This is why the single-accent rule from the shared system didn't survive: clinical
  status genuinely needs more than one signal.
- **Fraunces / Inter / JetBrains Mono.** A serif display face reads clinical-but-human rather than
  startup-generic; all data is mono and tabular so digits align down a column.

## Infrastructure

- **`idb` wrapper over raw IndexedDB** — small, typed, no framework lock-in.
- **pdf.js takes no `isEvalSupported` flag.** v6 removed both the option and the eval-based font
  path it guarded; passing it is a type error and a no-op. A CSP without `unsafe-eval`, limiting
  egress to `api.anthropic.com`, enforces the same property at the browser level.
- **Browser verification is part of the suite.** Unit tests can't prove the pdf.js worker loads,
  IndexedDB persists, or the wipe control empties storage. `npm run verify:ui` drives the built
  static export in headless Chromium through the real ingest pipeline and fails on any console
  error.
