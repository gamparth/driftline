# Driftline — Health Records Timeline

## Problem

Lab results live in per-visit PDFs from different labs with different layouts, units, and reference ranges. Nobody sees the longitudinal picture: is creatinine drifting up over three years? Did LDL jump since the last statin change? Driftline turns any pile of lab-report PDFs into one local, private, longitudinal record with trends, drift flags, and a prepared question list for the next doctor visit.

## Scope

**In:** PDF ingest (pdf.js, client-side) · extraction to strict schema `{marker, value, unit, referenceRange, sampledAt, lab}` (zod-validated; LLM path retries once then routes to needs-review) · deterministic unit normalization (mg/dL↔mmol/L etc.) · marker timeline dashboard (line/sparkline per marker, shaded reference band, out-of-range points in accent) · rule-based drift flags (outside reference range; >20% move between consecutive samples) · LLM "questions for your doctor" generator fed only flagged drifts · demo mode with synthetic reports · IndexedDB persistence (versioned) + wipe control · BYO Anthropic key (localStorage, verified on save, browser→API direct).

**Out:** diagnosis or medical advice (UI states this explicitly) · wearables · imaging · sharing/export · server-side anything.

## Architecture

Next.js static export, 100% client-side. Layers:

```
PDF file → pdfText (pdf.js) → extractor → zod validate → normalize units
                                   │                          │
                    heuristic parser (deterministic)     store (IndexedDB)
                    LLM extractor (BYO key) fallback          │
                                                    timeline series builder
                                                    drift engine → flags
                                                    flags → LLM question generator
```

- **Extraction is heuristic-first.** A deterministic parser handles tabular lab layouts (marker/value/unit/range patterns). When it yields nothing (or per-row confidence is low) and a key is present, the LLM extractor structures the raw text to the same zod schema. Heuristic path is what the golden suite verifies; LLM path is tested with mocked responses (retry + needs-review behavior).
- **Engine = pure TS modules** under `lib/engine/` (parse, normalize, series, drift), no React imports, all TDD with golden fixtures.
- **Fixtures:** 4+ synthetic lab PDFs, distinct layouts, generated by a committed script (`scripts/generate-fixtures.ts`, pdf-lib) with hand-authored expected-value JSON beside each.
- **Storage:** `idb`, browser-local DB with stores for reports, review items, and questions. Dedup by content hash so re-upload changes nothing.

## Screens

1. **Landing** — promise, privacy statement (nothing leaves the machine), medical disclaimer, demo button.
2. **Upload** — drop zone, per-file extraction status, needs-review queue.
3. **Timeline dashboard** — marker grid with sparklines, flag chips, monthly/overall summary.
4. **Marker detail** — full line chart with reference band, sample table, drift history, generated questions.

All data screens designed in empty/loading/data states.

## Metrics

- Extraction field-accuracy on golden fixtures (marker, value, unit, range, date) — printed by test run, quoted in CASE-STUDY.
- Drift-flag correctness on fixture with known anomaly.

## Definition of done

All synthetic PDFs extract to expected values · timeline renders multi-year trend · drift flags fire correctly on the anomaly fixture · medical disclaimer visible · typecheck + build + tests green · README, DECISIONS, CASE-STUDY exist.
